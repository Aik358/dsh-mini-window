## 1. `dsh.client` 在 package.json 里的完整 schema

### 1.1 类型定义（权威）

【读到原文】`dev-package-manifest/lib/types/types.d.ts:76-89`

```ts
/** Client module declaration read by client-modules and the client build. */
export interface DshClientManifest {
    /** Client platform identifier; the Web consumer selects `web`. */
    platform: string;
    /** Informational package-name dependencies, not Cordis service injection. */
    inject?: string[];
    /** Boot phase-one registration barrier; absent means the shared application batch. */
    immediately?: boolean;
    /**
     * Exact module-table requests beyond the implicit client baseline, including
     * subpaths such as `<pkg>/client`; absent means baseline externals only.
     * Type-only imports are erased and create no module request.

```

挂载点【读到原文】`types.d.ts:25`（`dsh?: DshManifest`）→ `types.d.ts:36`（`client?: DshClientManifest`）。

### 1.4 ⚠️ `inject` 的双重语义（冲突，必读）

**同一字段名 `inject` 在两处含义不同，且由两套代码各自消费：**

- 【读到原文】`dev-package-manifest/lib/types/types.d.ts:79-80`：`dsh.client.inject` = **"Informational package-name dependencies, not Cordis service injection."**（模块图依赖边 → 决定 factory 到达顺序）
- 【读到原文】`GLOBAL\dsh-client-modules\lib\types\client\manifest.d.ts:40-47`：同一 `inject` 又被描述为 **"Cordis separately uses the same package edges to compose entries"**（Cordis 插件组合边）

⇒ **结论**：`dsh.client.inject` 同时喂给「模块 factory 预取顺序」和「Cordis entry 组合」两条通路。写值时**填包名**（不是服务名）。
⇒ 与之并列的、**真正**的 Cordis 服务注入是模块**导出的 `inject` 数组**（见 §2.3），填的是**服务名**（如 `["slots"]`）。

### 2.1 注册调用签名（权威 .d.ts）

### 2.2 真实 client.js 原文（最小可照抄范本）

【读到原文】`PROFILE\dsh-client-ui-brand-official\lib\client.js:1-48` —— 全文 48 行，最短的官方客户端插件：

```js
window.__ModuleLoader__.load({
	id: "@deepseek-ai/dsh-client-ui-brand-official",
	factory: (require) => {
		var module = { exports: {} };
		var exports = module.exports;
		Object.defineProperty(exports, Symbol.toStringTag, { value: "Module" });
		let react_jsx_runtime = require("react/jsx-runtime");
		let _deepseek_ai_dsh_client_ui_primitives = require("@deepseek-ai/dsh-client-ui-primitives");
		// ... 组件定义 ...
		const inject = ["slots"];
		function apply(ctx) {
			ctx.slots.inject("sidebar.brand.mark", () => ctx.slots.inject("sidebar.brand.name", function* () {
				yield ctx.slots.register({ name: "sidebar.brand.mark" }, OfficialBrandMark);
				yield ctx.slots.register({ name: "sidebar.brand.name" }, OfficialBrandName);
			}));
		}
		exports.apply = apply;
		exports.inject = inject;
		return module.exports;
	}
});
```

### 2.3 导出形状（契约核心）

**必须导出**（由 Loader 当「对象插件」消费）：

| 导出 | 必需 | 出处 |
|---|---|---|
| `apply(ctx)` | ✅ | 【读到原文】`PROFILE\dsh-client-ui-layout\lib\types\client\index.d.ts:135`、`dsh-client-ui-brand-official\lib\client.js:42` |
| `inject: string[]` | 视需要 | 【读到原文】`dsh-client-ui-layout\...\index.d.ts:127-128` 注释原文：**"Required services (cordis fiber inject — the loader passes all module exports as an object plugin)."** |
| `name` | 可选 | 【读到原文】`dsh-better-display（参考项目）\lib\client.js` 尾部 `exports.name = name;` |

**关键机制**（【读到原文】`dsh-client-ui-layout\...\index.d.ts:127` 注释）：**模块级的 `export const inject = [...]` 是 Cordis 服务注入声明**，填**服务名**。这与 §1.4 的 `dsh.client.inject`（填包名）是两套东西。

### 2.4 懒执行语义（写在 .d.ts 头注，权威）

【读到原文】`GLOBAL\dsh-client-modules\lib\types\client\manifest.d.ts:8-16`：
> 执行 plugin bundle **只注册 factory**；**每个模块主体副作用（包括 CSS 注入）都在 factory 闭包内，在物化时运行**，不在脚本执行时运行。
> 物化（`factory(require)` → exports）在首次 import/require 时发生，并在 `ClientModuleLoader.loadCache` 记忆化。
> 解析分支顺序：seed word → shell instance；memoized record → exports；graph row → 注册依赖 factory 与自身 factory；registered factory → 物化；**其他一切 → throw**（响亮失败，是构建期 bundle 纯净门禁的运行时镜像）。
【读到原文】`manifest.d.ts:68`：`require` **循环会抛异常**（factory 形式的 CJS 无法提供部分导出）。

### 2.5 ES module 语法可用吗？（重要）

⚠️ **未实证的争议点**：
- 【读到原文】`dsh-better-display（参考项目）\lib\client.js` 是 tsdown/rolldown 产物，`factory` 内的 `var __hasOwnProp = ...` 等属于**打包后内联**的 CJS 互操作样板，不能据此判定 ESM 语法可用。
- 【读到原文】`GLOBAL\dsh-client-ui-deliverables\lib\client.js:1` 以 `import{...}from"..."` 开头 —— 但该文件**未包含** `factory`，是 `exports["./client"]` 之外的**源码子路径**（`"./src/*": "./src/*"`），**不是** bundle 入口。据此判断 ESM 可用是**错误**的。
- **可确证的是**：`window.__ModuleLoader__` 是经典脚本全局，facade 的 `loadBundle` 默认「同源 classic `<script src>` 元素」（【读到原文】`manifest.d.ts:195-196`：*"Defaults to a same-origin classic `<script src>` element."*）⇒ **入口必须是经典脚本，不能依赖 `import`/`export` 顶层语法**。
- 【推测】因此 `factory` 体内应写 CJS 形态（`var` / `function` / `module.exports`）。这是被入口加载方式**强约束**的结论，但未见官方正面文档明确禁止 ESM。

### 2.6 宿主侧还有一道硬校验

【读到原文】`GLOBAL\dsh-client-modules\lib\index.js:466-472`（modules bootstrap 自检）：
```js
const exports=registration.factory(...)
if(typeof exports!=="object"||exports===null||typeof exports.createClientModuleSystem!=="function"||typeof exports.apply!=="function"){
  throw new Error("client-modules: <id>/client.js did not export the bootstrap module face")

```
⚠️ 这条**只针对 `dsh-client-modules` 自身**的 bootstrap 校验（要求 `createClientModuleSystem` + `apply`），**不是**普通插件的通用要求。普通插件按 §2.3 导出即可。

### 5.4 external 规则（决定能 require 什么）

【仅白皮书描述】`PROFILE\dsh-client-modules\README.zh.md:46`：
> 外壳初始化一张冻结的模块表（`PLATFORM_MODULES`：React、Cordis 与静态 UI 库）；**每个动态 bundle 都精确针对该基座解析其 external**。`dsh.client.external` **只添加基座之外的精确请求**；系统会把每个请求解析到其指定的动态包 row 或完全匹配的静态表键。**纯类型 import 会被擦除，不产生请求**。组合阶段会**拒绝畸形请求、缺失提供方、自请求与同步请求环**。

**照写规则**：
1. `require("react")` / `require("react/jsx-runtime")` / `require("react-dom")` / `require("@deepseek-ai/cordis")` / `require("@deepseek-ai/dsh-client-ui-slots")` / `require("@deepseek-ai/dsh-client-ui-primitives")` / `require("@deepseek-ai/dsh-client-store")` ⇒ **基座已含，无需声明 external**。
2. 要 require **另一个插件的客户端半侧** ⇒ `require("<包名>")` 或 `require("<包名>/client")`（二者等价，见下），且必须在 `dsh.client.external` 里列出 `<包名>/client`，并在 `dsh.client.inject` 里列出 `<包名>`。
3. **不要** require `dsh-client-ui-dockkit`（§5.2）。

⇒ **`<pkg>` 与 `<pkg>/client` 解析到同一组导出**。

## 6. bundle 构建要求 —— 有免构建写法（重要）

### 6.1 白皮书说什么

【仅白皮书描述】`PROFILE\dsh-client-modules\README.zh.md:48-50`：
> **构建要求**：宿主提供的是**已构建的**客户端 bundle，因此启动前 `pnpm run build` **必须已产出每个 `lib/client.js`**；缺失 bundle 会**明确导致激活失败**，并给出一条构建说明及包／路径列表。

### 6.2 代码怎么说（权威，且更精确）

【读到原文】`GLOBAL\dsh-client-modules\lib\index.js:170-180`：
```js
/** Resolve `exports["./client"]` to a relative path, accepting the string and one-level conditional forms. */

```
【读到原文】`:718-719`：`const clientRel = clientExportOf(packageName, pkg.exports); if (clientRel === void 0) throw ...`
【读到原文】`:723`：`clientPath: join(dirname(pkgPath), clientRel)`
【读到原文】`:795-820` `captureArtifactBaseline(clientPath)` / `initialBundleSnapshot(pkgName, clientPath)` → 失败抛 `MissingClientBundleError`。
【读到原文】`:132-140` `MissingClientBundleError` 携带 `packageName` + `clientPath`，`:152` 打印 `- package: ...  path: ...`。

### 6.3 ✅ 结论：产物形态是「**一个文件、位置由 `exports["./client"]` 决定**」，不是「必须是打包产物」

**硬要求（【读到原文】）**：
1. `package.json` 里必须有 `exports["./client"]`，且值是**字符串**（或带 `default` 字符串的对象）。
2. 该路径指向的文件**必须真实存在于磁盘**（否则 `MissingClientBundleError`）。
3. 该文件是**经典脚本**，调用 `window.__ModuleLoader__.load({id, factory})`（§2.1/§2.5）。
4. `factory` 返回一个对象，含 `apply(ctx)`（§2.3）。

**没有任何构建器、打包器、ESM、源码映射的强制要求。**
- `dsh-better-display` 用 **tsdown**（`package.json` `scripts.build = "tsc -p tsconfig.json && tsdown"`）。
- **`dsh-auto-memory` 的 `lib/client.js` 是手写的**（`dsh-auto-memory（参考项目）\lib\client.js:1` 首行原文注释：*"dsh-auto-memory — browser half (**hand-written `__ModuleLoader__` bundle**)"*），2,199,370 字节，头部直接 `window.__ModuleLoader__.load({`，**无打包器**，`package.json` 里**无 `scripts.build`**。

### 6.4 ⚠️ 与白皮书的冲突（必须指出）

| 白皮书表述 | 代码/真实插件事实 | 裁定 |
|---|---|---|
| 「启动前 `pnpm run build` **必须已产出**每个 `lib/client.js`」 | 路径并非硬编码 `lib/client.js`，而是 **`exports["./client"]` 解析出的任意路径**（`index.js:718-723`）；且**存在手写免构建的真例**（`dsh-auto-memory`） | **白皮书表述不准确**。真实规则是「**该文件必须已存在**」，与是否 `pnpm run build` 无关 |
